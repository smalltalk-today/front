# GitHub Projects·이슈

작업 보드: [Smart Talk Front](https://github.com/orgs/smalltalk-today/projects/2). `smalltalk-today/front` 저장소에 연결된 보드로, 두 명이 같은 이슈를 기준으로 진행 상황을 공유합니다.

## 상태

| 상태 | 기준                        |
| ---- | --------------------------- |
| 대기 | 아직 시작하지 않은 작업     |
| 진행 | 작업 중 또는 PR 리뷰 중     |
| 완료 | 완료 조건 확인 및 이슈 종료 |

`front`의 열린 이슈는 자동으로 보드에 추가됩니다. 새 항목은 대기로 시작하고, 이슈가 종료되면 완료로 이동합니다. 작업 시작 시 담당자가 진행으로 옮깁니다. 취소된 작업은 이슈 종료 사유를 기록합니다.

## 간단한 이슈 템플릿

| 템플릿    | 작성 항목                                          | Type    | 기본 라벨 |
| --------- | -------------------------------------------------- | ------- | --------- |
| 버그 제보 | 문제와 재현 방법 / 기대·실제 결과 / 수정 완료 조건 | Bug     | bug       |
| 기능 제안 | 필요한 기능 / 완료 조건                            | Feature | feat      |
| 일반 작업 | 작업 목적 / 완료 조건                              | Task    | chore     |

이슈 하나에 담당자 한 명을 지정합니다. 완료 조건은 확인할 수 있는 짧은 항목으로 작성합니다. 문서·스타일·테스트 등 작업에 맞춰 기본 라벨을 변경할 수 있습니다. 우선순위·일정·추정치는 필수로 두지 않습니다.

템플릿 파일은 `.github/ISSUE_TEMPLATE/`에 있습니다. 기본 브랜치 `dev`에 반영된 뒤 GitHub 이슈 생성 화면에 표시됩니다. 버그·기능·일반 작업 템플릿 중 목적에 맞게 선택합니다. 이슈와 dev 대상 작업 PR을 연결하고, 작성자 외 승인 1명과 필수 검사 통과 후 병합합니다. dev 병합 시 `Closes #번호`로 이슈가 종료되며, main 반영은 별도 dev → main PR로 진행합니다. [Git·PR 가이드](git.md)를 참고합니다.
